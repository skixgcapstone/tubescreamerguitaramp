# Raspberry Pi harness instructions

- Use this harness and its README to reach and inspect the Pi. Preserve SSH host-key verification; do not commit credentials or private keys. Supply machine-specific host settings through environment variables, flags, or the ignored local configuration.
- Check the current service and audio state before changing it. Do not interrupt an active performance or recording unless the user requests it or a test requires it. The `meter` command explicitly interrupts live playback, then attempts to restore the prior service state; verify recovery if the connection fails.
- The application launcher restores the Codec Zero mixer profile on startup, so temporary changes to gain or routing are not persistent. The codec's green speaker terminals are not its P2 AUX output. Refer to the tube-board schematic and deployment notes for the current audio path.
- Diagnose the display with its connector status, touch device, backlight, and power flags, but do not treat software detection or a screenshot as proof that the physical display is functioning. Verify the actual display model, cable, power and touch alignment before changing persistent configuration.
- The ELECROW HDMI replacement had not been connected when these instructions were written. Prefer display auto-detection; do not blindly apply older `config.txt` HDMI directives to the current KMS/Wayland stack. Record and preserve existing settings before edits.
- Remote desktop access must be limited to loopback and forwarded over SSH. The harness may start an unauthenticated local VNC listener, so use it only on trusted machines and stop it when no longer needed. A screenshot may be obtained with `screen` without enabling remote input.
- Hardware schematics and the team's quick-start guide are in `docs/hardware/tube-pcb/` and `deploy/`. Photos containing people or order labels are stored locally under the ignored `docs/hardware/tube-pcb/photos/` directory.
- After changing project code, run the relevant tests and `graphify update .` as required by the repository's root instructions. Report what was tested on the Pi and what still requires physical hardware verification.
